## coredata-sync

SUMMARY: Audited DataModel XML + CoreDataManager + CloudService (CloudSyncManager/CloudDataService/CloudRestoreService were merged into Services/Cloud/CloudService*.swift; CloudMLService no longer exists as named). Core Data delete rules are mostly correct (Player cascades to children, join entities nullify), but the sync/restore layer has serious integrity gaps: only profiles+sessions ever sync after onboarding (matches, plans, custom drills, avatar, stats, goals upload exactly once, at onboarding), local deletions never propagate to Firestore so deleted data resurrects on restore, restore is create-only with no rollback so a failed restore + retry persists duplicate Players, and the model has zero uniqueness constraints to backstop any of this. CoreDataManager deletes the entire store on any load error (migration failure = total local wipe) and save() silently swallows errors. Conflict resolution (mergeWithConflictResolution) exists but is dead code — two-device sync is blind last-writer-wins. Re prior claims in tasks/todo.md: "CloudSyncManager @MainActor" and "CloudRestoreService unsafe context param" are fixed in the merged CloudService; "full incremental sync redesign" remains unaddressed and is the root of the top findings.
